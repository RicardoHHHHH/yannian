# 研念使用指南

一个面向 **AI 研究、论文精读和 idea 发展的本地工作台**。Python 后端 + 浏览器界面；论文、项目、对话、idea 和报告保存到本机 SQLite 和 PDF 文件中。

## 开始使用

Windows：双击桌面的 **“研念工作台”** 快捷方式，或项目内的 **`start.cmd`**。首次运行会准备 Python 环境和依赖，然后打开 `http://127.0.0.1:8765`。启动器会复用已运行的研念服务，未运行时在后台启动；关闭启动窗口或浏览器不会停止后台服务。端口被其他程序占用时会提示，不会替换该程序。

移动或重新解压项目后，先运行一次 `start.cmd` 准备环境，再在项目目录执行 `powershell -ExecutionPolicy Bypass -File create-desktop-shortcut.ps1` 重建桌面快捷方式。后台启动日志保存在 `data/runtime/server.log`。开发调试需要随终端关闭服务时，使用下面的 `run.py` 启动方式。

也可以手动启动（Python 3.11+）：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py
```

macOS：安装 Python 3.11+ 后双击 `start.command`。如解压后缺少执行权限，先在终端进入项目目录执行 `chmod +x start.command start.sh`。Linux 或希望使用终端时：

```bash
bash start.sh
```

统一启动器首次创建环境并安装依赖，后续按依赖清单指纹跳过重复安装。依赖升级失败可直接重试；发现其他操作系统复制来的 `.venv` 时提示重建，不删除资料。跨平台迁移保留 `data/`，在目标系统重新建立 `.venv/`。macOS 双击启动的 PATH 会补充常见 Homebrew 和用户安装目录；特殊 Python 路径可设置环境变量 `YANNIAN_PYTHON`。Codex 需在 PATH 可见，或在 `.env` 指定 `YANNIAN_CODEX_BIN`。

可把 `start.command` 的替身放到桌面。Windows 调试可执行 `start.ps1 -Foreground`，macOS / Linux 执行 `bash start.sh --foreground`，Ctrl+C 停止。

端口冲突时可使用 `python run.py --port 8766`。自动打开浏览器不符合你的偏好时，追加 `--no-browser`。

## 连接模型

**当前版本默认连接本机 Codex，使用已登录 ChatGPT 账户的 Codex 额度，无需 API Key。** 打开左下角 **模型设置**，连接方式选择“本机 Codex”，检测登录后即可提问。默认跟随本机 Codex 的模型，也可以选择检测到的模型和思考深度。

### 本机 Codex（默认）

- 通过官方 **Codex App Server** 的 stdio 协议运行。已在 Windows / Codex CLI 0.153.4 验证，其他版本需支持 `thread/start`、`turn/start` 和环境选择等协议字段。
- 自动查找 PATH 中的原生 `codex` 或 Codex Desktop 安装目录。特殊安装路径可在 `.env` 设置 `YANNIAN_CODEX_BIN`，指定原生可执行文件；不通过 shell 执行 `.cmd` / `.bat` 包装脚本。
- 如果提示未登录，在终端运行 `codex login` 并选择 ChatGPT 登录，然后点击“重新检测登录”。登录凭据由 Codex 自己管理，研念不提取或复制 token。
- 仅接受 ChatGPT 登录。本模式不会使用环境中的 API Key，账户额度不足时提示等待，不会自动改用 API 计费。
- 问答、图像理解、语义归类、idea 分析使用同一连接。论文、历史对话及勾选的 PDF 页图像会发送给 Codex 处理；不会读取当前 Codex 窗口的聊天或继承它的记忆。
- 检测登录不发送模型请求。“保存并测试”发送一条简短真实请求，会消耗账户额度。
- 每次请求使用临时 Codex 会话；工作台负责保存和重新提供段落对话历史。不会把每段论文问答创建成侧栏里的长期 Codex 任务。
- 连接仅用于研究问答，禁用本地环境、shell、插件、应用、浏览器操作及多代理工具；只有用户勾选联网分析时开启 Codex 的 web 搜索。不会改写你的全局 Codex 设置。
- 当前同一时间处理一条 Codex 请求；并发点击会提示等待。单次超时约 6 分钟。输出长度为提示中的目标，不是硬性 token 上限；长文本、深度推理和搜索都会消耗更多额度。

### DeepSeek 与其他兼容模型

1. 打开“模型设置”，选择 **DeepSeek**。自动填入 `https://api.deepseek.com`、Chat Completions 协议与 `deepseek-v4-flash`。
2. 填写自己的 DeepSeek API Key，点击“保存并测试”。也可在本机 `.env` 设置 `DEEPSEEK_API_KEY`，重启服务后选择该预设。
3. 可选择 `deepseek-v4-pro`；框选图片需视觉模型，例如 `deepseek-v4-flash-vision-exp`。模型能力和可用性以服务商账户与 [官方文档](https://api-docs.deepseek.com/) 为准。
4. 默认关闭 DeepSeek 思考以便快速回应；对话区可选择快速、深入或最大思考。开启后请求的输出上限提高到至少 16,384 tokens，由思考与正文共享；实际用量由服务返回，可能更慢、用量更多。界面只显示思考状态与最终正文，不保存推理过程。

其他服务选择 **其他兼容 API / 本地模型**，填写基础地址与模型 ID，再选择 Chat Completions 或 Responses。不要在基础地址后附加 `/chat/completions` 或 `/responses`。手动确认是否支持图片和思考参数；本机免密服务可勾选“不需要 API Key”，仅允许 localhost / 回环地址。远程服务须使用 HTTPS。

“保存并读取模型列表”使用所填地址的 `/models`；服务不支持列举时，仍可手动输入模型 ID。不同 API 地址的对话模型偏好相互独立。切换服务地址会清除本次密钥，环境变量中的 Key 只用于其配置的目的地址，避免误发给另一家服务。

Chat Completions 支持流式正文、停止生成、保留部分回答与上下文续聊。文本模型收到图片时会明确要求切换视觉模型，不会悄悄丢弃图片。DeepSeek 和通用兼容接口未接入模型联网工具，额外官网补查会标记不可用；学术索引、查询扩展、候选初筛和基于候选的 idea 分析仍可使用。

### OpenAI API（可选）

在连接方式中主动选择“OpenAI API”后，填写 API Key、API 模型 ID 和基础地址。默认地址为 `https://api.openai.com/v1`，默认 API 模型 ID 为 `gpt-6-astra`，可以改成 API 账户可用的模型。这条路径单独按 API 计费。

- 使用 OpenAI **Responses API**。兼容服务必须支持 `/responses`；联网分析还需要支持 `web_search`，图表提问需要支持图像输入。
- 所有 API 模式的对话同样独立保存在研念中。
- 在界面输入的 Key 仅保留在服务进程内，重启后需要重新填写。它不会出现在 `GET /api/settings`、浏览器存储、SQLite 或导出备份中。
- 如需长期保留配置，把 `.env.example` 复制为 `.env`，在本机编辑。不要把 `.env` 提交到代码仓库或发给他人。
- API 模式没有 Key 时会提示配置；也可以切回已登录的 Codex 模式。PDF 阅读、本地归类、idea 保存和备份无需模型连接。
- API 与联网搜索的实际费用、模型访问权和限额由所用服务账户决定。

## 一次完整的研究流程

1. **建项目**：例如“可靠的 LLM Agent”或“多模态推理”。在描述中写下研究问题和中英文关键词。
2. **导入论文**：在“发现论文”顶部粘贴 PDF 或论文网页网址，选择归入项目后点击“下载并保存”。也可在检索结果中点击“获取 PDF 并阅读”，或打开已收录文献后点击“自动获取 PDF”。支持拖入 PDF、输入 arXiv 编号 / 链接及从本机 Zotero 选择条目。
3. **逐段精读**：默认打开 PDF 原文。选择工具栏“选中文字”，在原页拖选句子或段落，点击“问选中文字”，在右侧输入问题并发送。
4. **核对证据**：点击回答中的页码或“选区”引用回到原 PDF 位置。辅助“文字提取”视图保留旧版段落快捷提问。
5. **看图表**：选择“框选图片/区域”，在图片、公式或流程图外拖出矩形，点“分析选中区域”。右侧显示将发送给模型的裁剪预览，确认问题后发送。也可以额外勾选所在整页。
6. **随手记 idea**：选中文字或区域后点“记为 idea”；原文、页码和选区关联一起保存。新 idea 的未提交草稿会自动存到浏览器本地。
7. **发展想法**：在 idea 工作页运行“有没有类似工作”“找代码与数据集”或“设计验证实验”。报告、检索关键词、时间和来源都会保留。
8. **整理文献**：本地相似归类按词项重合生成建议；AI 语义归类按研究问题与方法生成建议。可以调整新项目名，再应用选中的结果。一篇论文可归入多个项目。

论文对话会自动持久化。右侧“历史对话”可打开旧记录，“查看上下文”提供消息目录与最近一轮参考原文。同一篇论文切换段落或选区后会继续当前对话；点击“＋ 新对话”才开始独立记录。不同论文的上下文保持独立。

## 对话、模型与停止

- **调整左右宽度**：在宽屏阅读页拖动 PDF 和对话之间的分隔条。双击恢复默认比例；聚焦分隔条后可用左右方向键微调、Home 复位。比例保存在当前浏览器，PDF 保持当前阅读位置；小屏幕改为上下排列。
- **回看上下文**：对话消息区单独滚动。向上看旧消息时，新回答不会把你拉回底部；点“回到最新消息”继续跟随。顶部只保留一行当前关注范围；点击“查看上下文”可按需查看原图与辅助文字。
- **切换模型和思考深度**：在输入框上方选择。Codex 选项来自本机可用模型列表，思考档位随模型变化；仅支持文字的模型不能接收图片。点击刷新按钮重新读取列表。选择对下一条问题生效，正在生成的回答仍使用发送时的设置；不会覆盖论文发现等功能的默认设置。API 模式可手动填写或读取模型列表，思考档位按预设和明确的服务能力提供；模型与地址偏好相互隔离。
- **停止与继续**：Codex 与 Chat Completions 回答逐步显示。点击“停止”会取消后台模型请求，保留问题和已输出内容，并标记未完成；之后可以追问。Responses 模式等待完整响应时也可取消连接，尚未返回的文字无法保留。
- **刷新恢复**：已发出的问题、答案和任务状态在本机保存，重开论文会恢复最近对话；输入草稿单独保存在浏览器。页面刷新不会取消后台回答。服务重启时，未完成的回答会标为中断。

本轮会带入最近最多约 80,000 字符的历史文字和检索出的原文；完整历史仍可在界面查看，超过上限时上下文窗口会说明省略数量。当前选区会继续随追问发送；历史中的其他图片保留来源与文字记录，点击缩略图可重新选为当前关注并分析像素内容。思考深度调整模型的推理投入，界面只显示状态与公开回答。

## PDF 下载进度与速度

“发现论文”的网址导入会显示连接来源、下载文件、解析保存等阶段；传输时显示已下载大小、平均速度和耗时。来源未提供文件总大小时使用不定进度，不显示猜测的百分比。

4 MB 以上、提供字节范围及强 ETag 的 PDF 可通过四路分段传输加速。每段均检查文件标识、范围和长度；不支持或校验失败时回退到普通下载。下载速度仍取决于来源及网络，同网址已保存的文件会直接复用。下载和本地解析不调用模型。

## PDF 原文与选区阅读

框选图片后，输入框旁显示紧凑的待发送附件，可在发送前移除。发送成功后，图片变成问题上方的小缩略图，随消息一起滚动，不再固定占据顶部；同一图片的连续追问只在首次使用处展示缩略图。点击缩略图可回到 PDF 选区，完整预览和“辅助文字”在“查看上下文”中按需查看。模型收到的仍是原图裁剪及辅助文字，连续追问保留当前选区。旧对话也使用这种展示方式，原始记录保留。

**取消框选**：按 Esc 退出框选模式，清除正在拖动或已经选中的矩形，并收起选区菜单及待发送附件。阅读页码、问题草稿和已发送的记录保留；此操作不会停止正在生成的回答。弹窗、下拉选择及输入法正在处理键盘输入时，Esc 优先用于当前控件；返回 PDF 后可继续取消框选。

回答和 idea 报告中的 LaTeX 使用本地 KaTeX 排版，支持 `$…$`、`$$…$$`、`\(…\)`、`\[…\]` 和常见矩阵、分段函数环境。长公式可横向滚动，代码块保留原样。公式尚未生成完整或语法不支持时，可以展开原文继续检查；不会自动改写公式含义。

阅读区外侧有独立的页面滚动条：在 PDF 框外滚动可将整个阅读框调高或调低，也可点击“阅读区置顶”或“论文信息”。PDF 框内的滚动只负责论文连续翻页。顶栏始终保留“收起 / 展开导航”和“收起 / 展开对话”按钮；两侧栏可独立隐藏，状态保存在当前浏览器。切换侧栏不清除问题草稿或重建 PDF 阅读器；点击选区提问会展开对话栏。

使用随项目提供的 **PDF.js 6.3.289** 渲染原始 PDF，保留页面布局、字体、公式、图片和双栏排版。默认连续滚动：鼠标放在 PDF 阅读区，向下滚动即可接着看下一页，向上滚动可返回上一页，工具栏页码随阅读位置更新。也可通过页码输入框和左右箭头跳页。支持适应宽度和 100%–400% 缩放；文本选择层覆盖在原页上，显示内容不会重新排版成大段文字。

原始 PDF 完整保存，不压缩、不转成低清图片。阅读器默认至少 4 倍采样，屏幕像素密度超过 4 倍时按更高密度绘制；放大、改变阅读区宽度或屏幕像素密度后重新绘制并保留阅读位置。页面按屏幕附近的区域分块渲染，每块不超过 2,048 × 2,048 像素，移出视野后释放，不再因整页像素上限降低采样倍率。高清渲染会增加计算和内存开销；原 PDF 内嵌低分辨率图片的细节仍受原文件限制。

长论文只渲染当前阅读位置附近的页面，远处页面保留尺寸占位并释放画布。切换选择工具不会重建阅读区；缩放或调整窗口宽度时保留页内阅读位置。翻页不会清除右侧已输入的问题，已选区域始终绑定其原始页码。

选中文字后发送原文摘录与相关上下文；框选区域后由本机从原 PDF 裁剪图像，再把裁剪图及区域文字发送给模型，右侧预览和模型收到的裁剪图来自同一选区。选择操作本身不调用模型，点击右侧“发送”才发起分析。

选区使用页面比例坐标保存在 SQLite 中，缩放和窗口大小变化后仍能定位。页面自身的旋转和 CropBox 裁切也纳入坐标转换。对话与 idea 会保存选区 ID，重开历史对话或点击引用可回到原区域；带 `page` / `selection` 的页面地址可在刷新后恢复。

目前一次选择位于同一页，框选为矩形，不支持跨页连续选区或自由手绘。扫描 PDF 没有文字选择层时，使用“框选图片/区域”直接提问。选区保存在工作台中，不修改原始 PDF 文件。

## 自动获取 PDF

- **通过网址导入**：“发现论文”顶部提供独立入口，输入公开 PDF 直链或论文详情页网址，选择归入项目后下载保存，不调用模型。支持 arXiv、OpenReview、ACL、CVF 论文页及包含论文 PDF 元数据或唯一 PDF 附件的网页；一个网页包含多个不明确的 PDF 链接时会要求使用具体直链。下载后从网页元数据或 PDF 识别标题，分行标题会合并；已有同网址 / 相同文件会复用并添加所选项目归类。失败时保留输入供重试，不新建空文献。成功后点击“打开阅读”，发现论文的检索结果仍保留。
- **发现论文**：每条结果都有“获取 PDF 并阅读”，先收录到所选项目，再查找公开原文、下载、解析并打开阅读页。
- **已有文献**：打开只有元数据的文献，点击“自动获取 PDF”。文件附在原文献 ID 下，已有项目、idea 和对话保留。已有 PDF 时直接使用本机文件，不重复下载。
- 优先使用 arXiv 编号、原论文链接和会议来源。支持 arXiv、OpenReview、ACL、CVF，以及 NeurIPS、PMLR、期刊页面中的标准 PDF 引用元数据。
- 原链接不可用时，继续查 DOI 落地页、Crossref 登记全文、Semantic Scholar 开放全文和 arXiv 同标题预印本。按标题寻找替代版本时，要求规范化标题一致，不把仅仅相似的论文当成原文。
- 下载无需 Codex / OpenAI 模型请求。仅访问公开 HTTPS 来源，不提取浏览器登录信息；付费墙、登录要求、验证码及来源限流可能阻止下载，此时显示已尝试来源和原因，提供重试及原文入口。
- PDF 保存到本地 `data/papers/`，保留下载来源和时间；使用 arXiv 文件时在阅读页标明“arXiv 版本”，可能与正式出版版本不同。每次自动查找最多约 150 秒，PDF 限制 40 MB / 500 页。HTML 登录页、明显非 PDF 和损坏文件不会作为正常附件保存。

桌面快捷方式、网页图标及左上角品牌已统一为研念的绿色书页 Logo。图标包含 16–256 像素的 7 个尺寸，适配 Windows 桌面缩放；重新运行 `create-desktop-shortcut.ps1` 可以更新快捷方式的图标路径。

## Zotero 导入

需要支持 Local API 的 Zotero 版本，并保持 Zotero 打开。进入 **设置 → 高级 → 允许本机其他应用程序与 Zotero 通信**，然后在研念中点“从 Zotero 导入”。

- 从 `http://127.0.0.1:23119/api/` 读取本机个人库，支持分页选择，每批最多 100 条。
- 复制文献元数据及第一个本机 PDF 附件。原 Zotero 文件保留。
- PDF 尚未下载到本机时先导入元数据，之后可附加 PDF 或重试导入。
- 本版是导入，不是实时双向同步；研念中的项目、idea 和对话不会写回 Zotero。
- 尚未覆盖 Zotero 群组库、批注迁移、多个 PDF 附件选择和移动端插件。

## 发现论文：多查询、分页和优先阅读

发现论文默认使用“深入检索”，支持直接输入中文研究问题，例如 **“医疗领域 agent 和世界模型”**。

1. 模型展开为互补的英文查询，并加入已识别的术语别名。多个方向会分别检索，避免把所有词强制同时匹配。
2. **Semantic Scholar、arXiv、Crossref** 分别检索最多 6 条查询，每条最多 2 页、每页 50 条；不足一页时停止该查询翻页。每个来源独立进行，瞬时错误重试，限流按来源规则退避。
3. 勾选“补查会议与论文官网”时，模型实际联网寻找最多 25 个论文页面。程序逐一核验 arXiv、OpenReview、NeurIPS、PMLR、ACL Anthology、CVF 等白名单网站的引用元数据；没有核验通过的链接不混入候选。
4. 按 DOI、arXiv 编号及规范化标题合并重复文献，保留来源链接和更完整的元数据。**保留合并后的候选**，结果以每页 24 篇展示。标题保留来源原文，默认显示英文标题，可切换全部标题语言。
5. 模型根据候选标题与摘要整理最多 30 篇优先阅读论文，附中文相关性理由和方向标注。初筛覆盖本地相关性前 100 篇及官网补查论文，最多 125 篇；全部其他候选仍保留。医疗问题会区分医疗 Agent、医疗世界模型、临床模拟 / 相邻方法、通用基础方法。

界面显示真实请求、返回页数、候选数量、英文查询和失败原因。模型扩展、来源检索、官网核验、阅读初筛完成后才结束本轮任务；没有人为增加等待时间。来源失败时明确标记“覆盖不完整”，并保留成功结果。可停止并保留已找到的结果；检索记录保存到本地 SQLite，带 `#search=...` 的页面地址可在刷新后恢复。服务重启会中断未完成任务并保留已有结果。

深入检索中的术语扩展、官网补查和阅读初筛会消耗所选连接的模型额度，通常需要数分钟。快速检索仅查询各索引第一页，不调用模型。检索式扩展或初筛失败时会明确提示，并保留索引结果。

## 论文推荐与 idea 分析的证据边界

返回的候选数量不等于相关论文数量。官网核验确认页面的论文元数据，不代表已阅读全文；阅读初筛基于标题及摘要片段，不证明实验结论。一次检索有查询数、分页和时间范围，仍可能漏掉论文。

会议筛选支持 NeurIPS、ICML、ICLR、CVPR、ICCV、ACL、EMNLP，仅依据检索结果返回的会议元数据。缺失元数据的论文可能被筛掉，arXiv 预印本不等于会议已录用。本版还不是完整的顶会论文索引。

idea 分析先提炼 / 接收英文关键词，取得候选元数据，再调用模型分析；允许联网时要求模型使用 web search 补充并核查论文、作者代码和数据集主页。提示词要求区分全文证据、摘要信息、推断和假设，不能把“没搜到相同工作”当成创新性证明。结果仍需要研究者核实。

## 当前版本的限制

- PDF “段落”目前是 PDF 文字块，含页码和坐标；不是经过语义校正的论文段落。标准双栏有阅读顺序启发式，复杂跨栏、脚注、公式和表格可能提取不佳，应看原文。
- 本版没有 OCR。扫描件可看原文，通过框选区域或附上整页图像提问。
- 段落问答使用本地词项检索及邻近上下文，不是全量全文塞入，也未建立 embedding 索引。模型会看到覆盖数量提示。长论文跨章节问题可能漏检证据。
- 相似论文推荐是关键词检索候选；不保证穷尽最近邻或相关工作。AI 归类每次覆盖最近导入的最多 120 篇文献。
- AI 返回完成后一次性显示；当前未实现流式显示。长分析可能需要数分钟，请等待报告自动保存。
- 单文件限制 40 MB / 500 页；文献规模较大时 PDF 解析、页面图像生成和全量备份还需要进一步优化。
- 这是本地单人应用，只监听 loopback。没有团队账户、跨设备同步或公网部署配置。

## 数据与恢复

默认保存到项目的 `data/`：

```text
data/
  library.sqlite3       项目、元数据、段落、对话、ideas、分析报告、检索记录、PDF 选区
  papers/*.pdf          原始 PDF
  runtime/server.log    后台启动日志
```

可通过环境变量 `YANNIAN_DATA_DIR` 指定其他目录。**保留这个目录就保留了研究资料。** 不要把 `data/` 当作缓存删除。

左下角“导出备份”会生成 ZIP，包含一致性 SQLite 快照、原始 PDF、JSON 导出和 idea Markdown 文件，不包含 API Key。

恢复方法：先停止研念；把现有 `data/` 改名保留；将备份中的 `library.sqlite3` 和 `papers/` 放入新的 `data/`；再启动程序。ZIP 内的 `library.json`、`ideas/` 方便跨工具迁移。
